# Часть I. Файлы cookie и аналогичные технологии

## 2. Строго необходимые и функциональные технологии

Для работы интерфейса применяется локальное хранилище браузера (`localStorage`) — технология,
аналогичная cookie по назначению, но не передающаяся на сервер автоматически:

| Ресурс | Запись | Назначение | Срок |
| --- | --- | --- | --- |
| pir2pir.ru | `pir2pir.locale` | выбранный язык интерфейса | до очистки данных сайта |
| app.pir2pir.ru | токен сессии и отметка времени | вход в веб-приложение без повторной авторизации | до выхода или очистки данных сайта |
| docs.pir2pir.ru | настройки темы и языка | оформление документации | до очистки данных сайта |

Без этих записей интерфейс не сможет запомнить язык или сохранить вход, поэтому они применяются
всегда и не требуют отдельного согласия.

## 3. Аналитические технологии

Для оценки посещаемости и качества интерфейса применяется система веб-аналитики
**Яндекс Метрика**. Она устанавливает собственные файлы cookie:

| Файл | Назначение | Срок |
| --- | --- | --- |
| `_ym_uid` | обезличенный идентификатор посетителя | 1 год |
| `_ym_d` | дата первого визита на сайт | 1 год |
| `_ym_isad` | признак наличия блокировщика рекламы | 2 дня |
| `_ym_visorc` | текущая сессия записи поведения | 30 минут |

Собираются обезличенные сведения о посещении: обращения к страницам, источник перехода, тип
устройства и браузера, приблизительный регион по IP-адресу. Эти сведения используются в
статистическом виде и не применяются для принятия решений в отношении конкретного посетителя.

Оператором в отношении собираемых Метрикой данных выступает ООО «ЯНДЕКС» на условиях
[Условий использования сервиса Яндекс Метрика](https://yandex.ru/legal/metrica_termsofuse/).

## 4. Как отказаться

Управлять файлами cookie и локальным хранилищем можно средствами браузера: в настройках сайта их
можно запретить, а сохранённые данные — удалить («очистить данные сайта»).

Отдельно отказаться от Яндекс Метрики можно с помощью
[официального блокировщика Яндекса](https://yandex.ru/support/metrica/general/opt-out.html).

Отказ от аналитических технологий не ограничивает доступ к сервису. Запрет строго необходимых
технологий из раздела 2 не нарушает работу сайта https://pir2pir.ru, но делает невозможным
сохранение сессии в веб-приложении — вход придётся выполнять заново при каждом открытии.

# Часть II. Правила применения рекомендательных технологий

## 6. Общие положения

Настоящие Правила публикуются во исполнение части 3 статьи 10.2-2 149-ФЗ и описывают процессы и
алгоритмы, применяемые для предоставления информации на основе сведений об участниках сервиса.

Рекомендательные технологии применяются исключительно в одной функции — **подбор участников для
взаимных проверок учебных проектов**. Цель подбора (матчинга) указана в пункте 2 раздела 4
[Согласия](./consent.md).

Поиск участника по логину рекомендательной технологией не является: это детерминированный поиск по
точному совпадению и по началу логина, результат которого не зависит от предпочтений
запрашивающего. Поиск по имени и фамилии не выполняется.

## 7. Сведения, используемые для рекомендаций

Подбор выполняется на основании данных, перечень которых определён разделом 3
[Согласия](./consent.md):

| Сведения | Источник |
| --- | --- |
| Перечень учебных проектов и их статус | публичное API Школы 21, синхронизация профиля участника |
| Кампус и поток (волна) | публичное API Школы 21 |
| Review points и оценка обратной связи | публичное API Школы 21 |
| Проект и кампус, указанные в запросе на проверку | указывает сам участник |
| Настройки уведомлений | указывает сам участник |

Сведения, собираемые аналитическими технологиями (раздел 3), в подборе не участвуют: рекомендации
строятся только на данных учебного профиля и на запросе, который участник сформировал сам.
Содержание переписки участников, специальные категории персональных данных (статья 10 152-ФЗ) и
биометрические данные (статья 11 152-ФЗ) для рекомендаций не используются.

## 8. Как формируется подбор

Кандидаты отбираются и упорядочиваются по следующим правилам:

1. **Проект** — жёсткий отбор по точному совпадению кода учебного проекта. Участники, для которых
   проверка этого проекта недоступна, в подбор не попадают.
2. **Взаимность** — приоритет отдаётся парам, в которых оба участника ожидают проверки одного и того
   же проекта: такая пара закрывает потребность обоих.
3. **Кампус** — мягкое предпочтение участникам того же кампуса; подбор между кампусами допускается и
   не ограничивается.
4. **При прочих равных** — учитываются review points и оценка обратной связи как показатели опыта
   проверок.

Оператор не принимает на основании подбора решений, порождающих юридические последствия для
участника. Результат подбора носит рекомендательный характер: участник вправе отказаться от
предложенной пары, а сама проверка проводится на платформе Школы 21 и вне контроля оператора.

## 9. Контроль со стороны участника

Участие в подборе возможно только после регистрации и предоставления [Согласия](./consent.md).
Участник вправе в любой момент:

- изменить или отключить уведомления о запросах на проверку;
- отказаться от предложенной пары;
- удалить учётную запись в Telegram-боте — это прекращает применение рекомендательных технологий и
  влечёт отзыв Согласия.

Отдельного «выключателя» рекомендаций не предусмотрено: без подбора сервис не выполняет своей
единственной функции.
